# Contributing

Thanks for your interest in contributing to Cortexcn. Please take a moment to read this guide before you open a pull request.

## About this repository

This repository is a monorepo.

- We use [Bun](https://bun.sh) and [workspaces](https://bun.sh/docs/install/workspaces) for development.
- We use [Turborepo](https://turbo.build/repo) as our build system.
- We use [Biome](https://biomejs.dev), through [Ultracite](https://www.ultracite.ai), for linting and formatting.

It is the public part of the Cortexcn source: the docs website, the free components and blocks, the docs, and the registry. Cortexcn Pro (the Cortexcn and AI components, the charts, and the Pro blocks) and a few private parts of the site (sign-in, the admin pages, and the freelance studio) are not here. Where the site shows something built with Pro, this repository has a small stand-in that renders a placeholder card. A maintainer brings each accepted pull request into the main source, and the next sync updates this repository with it.

## Structure

```
.
├── apps
│   └── web                   the docs website (Next.js)
│       ├── app               routes and pages
│       ├── blocks            the page blocks, one folder each
│       │   └── <block>/files
│       ├── components        site components and docs demos
│       ├── content/docs      the docs pages, in MDX
│       ├── lib               site helpers and data
│       └── public/r          the built registry
├── packages
│   ├── ui                    the library
│   │   ├── registry.json     every free item, in the shadcn registry format
│   │   ├── scripts           registry build and checks
│   │   └── src
│   │       ├── agents        DESIGN.md and the agent skills
│   │       ├── components    the components
│   │       ├── examples      component examples
│   │       ├── hooks
│   │       ├── lib
│   │       └── styles        the design tokens
│   ├── icons                 the icon component
│   ├── eslint-config
│   └── typescript-config
└── templates                 free starter templates
```

| Path | Description |
| --- | --- |
| `packages/ui/src/components` | Component source. This is what `npx shadcn add` copies into a project. |
| `packages/ui/registry.json` | One entry per item: its files, dependencies, and metadata. |
| `apps/web/blocks/<block>/files` | Block source. The registry build copies it into `packages/ui/registry/blocks`. |
| `apps/web/content/docs` | The docs page for each component, with its props and examples. |
| `apps/web/public/r` | Generated by `bun run registry:build`. Don't edit it by hand. |

## Development

### Fork this repo

You can fork this repo by clicking the fork button in the top right corner of this page.

### Clone on your local machine

```bash
git clone https://github.com/your-username/ui.git
```

### Navigate to project directory

```bash
cd ui
```

### Create a new branch

```bash
git checkout -b my-new-branch
```

### Install dependencies

```bash
bun install
```

### Run the website

```bash
bun dev
```

The docs are at [localhost:4420/docs](http://localhost:4420/docs) and the blocks at [localhost:4420/blocks](http://localhost:4420/blocks).

### Check your change

```bash
bun run lint
bun run registry:build
bun run build
bun run check-types
```

Run `check-types` after `build` (or `dev`): the build writes the docs and Next.js types it needs.

`registry:build` validates every item in `packages/ui/registry.json` and rebuilds `apps/web/public/r`.

## Components

### Changing a component

1. Edit its source in `packages/ui/src/components/<name>.tsx`.
2. If you add a file or a dependency, update its entry in `packages/ui/registry.json`.
3. Update its docs page in `apps/web/content/docs/<family>/<name>.mdx` when props or behavior change.
4. Run `bun run registry:build`.

### Proposing a new component

Open an issue with the component request template first, so we can agree on the API before you build it. New components follow the same steps as above, plus a new entry in `registry.json` and a new docs page.

### Rules every change follows

- Components use the design tokens in `packages/ui/src/styles` for color and radius, and work in light and dark mode.
- Every interactive element works from the keyboard, shows a focus ring, and respects `prefers-reduced-motion`.
- No em dashes and no emojis in code, comments, or commit messages.

## Licensing

Everything here is MIT unless [NOTICE.md](./NOTICE.md) says otherwise. Only contribute code you wrote, or code whose license allows redistribution, and say where it came from in the pull request. We can't accept code from React Bits: its Commons Clause forbids redistributing it.

## Commit convention

Before you create a pull request, check that your commits follow the [Conventional Commits](https://www.conventionalcommits.org) convention, as in the history:

- `feat(components): ...` a new component or a new feature in one
- `fix(blocks): ...` a bug fix
- `docs(docs): ...` documentation only
- `chore(registry): ...` registry rebuilds and tooling

## Requests for new components

If you have a request for a new component or block, please open an issue on GitHub. We'll be happy to help you out.

## Security

Please don't report security problems in public issues. See [SECURITY.md](./SECURITY.md).
